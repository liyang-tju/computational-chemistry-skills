# 受控性能测试

仅当用户明确要求评测加速效果、选型硬件或调优并行参数（如 `KPAR`/`NCORE`/GPU 卡数）时才准备性能测试，不擅自占用集群资源跑大规模 benchmark。

## 1. 变量控制原则

- **固定一切科学参数**：测试目录之间保持完全相同的输入结构、`ENCUT`/`CUTOFF`、电子收敛判据 `EDIFF`、初态波函数、时间步长与轨迹输出频率。
- **禁止为提速私改物理模型**：不能通过偷偷调大 `POTIM`、放宽 `EDIFF`、改用 `LREAL = Auto` 或简化 k 网格来换取看似更高的吞吐；若需评估参数简化带来的加速与误差，必须作为独立的精度对照实验。

## 2. 测量窗口与记录字段

- 将**初始化/预热步**（如前 2–5 个 MD 步或首步 SCF）与**稳态步**分开计时，避免内存分配与初猜求解污染平均耗时。
- 汇总表至少包含以下字段：

| 测试项 | 硬件与布局 (`nodes × ranks × threads × GPUs`) | 软件标签 | 稳态耗时 (`s/step`) | 折算吞吐 (`ns/day` 或 `steps/h`) | 加速比 | SCF 平均迭代数 / 能量漂移 |
|---|---|---|---|---|---|---|

- 若改变并行参数（如 `NCORE` 或 MPI 数）导致 SCF 迭代次数明显上升或温度行为异常，应在性能报告中显式标注，不可只看单步墙钟时间。
