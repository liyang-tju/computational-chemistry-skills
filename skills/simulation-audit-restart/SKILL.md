# 计算审计与续算

从现有文件判断一项计算完成到了哪里，并为实际需要恢复的部分建立明确续算边界。

## 工作流程

1. 按计算批次和物理协议列出目标：步数、时长、收敛判据、模型产物或采样窗口。分别识别同一任务的原始段与后续段。
2. 对照调度记录、程序日志、完整轨迹帧、能量序列、最终结构和工作流标记。标注各项证据来源与观察时间。
3. 区分运行结束、达到目标、数值稳定、结构保持和统计收敛。没有充分证据的项写明未知；退出码为零不能代替科学判据。
4. 确认最新完整且互相匹配的检查点；核对原子顺序、晶胞、速度、电子态和所需偏置状态。受损轨迹尾部不作为续算依据。
5. 为剩余计算准备新的目录并记录父段、检查点步数、累计时间、还需运行的量及保留或重置的状态。用户已明确要求直接续算且检查点已验证时，不额外插入无关诊断或试跑。
6. 合并分析数据时，父段仅保留到选定检查点，子段仅保留其后的帧；保存原始段，不就地截断原文件。
7. 提交或停止操作遵循已有授权；需要停止且软件支持时优先使用其正常终止机制。

## 按需参考

- 引擎检查点与恢复边界：读取 [检查点](references/checkpoints.md)。
- 数值异常及科学完成判断：读取 [审计判据](references/completion.md)。

## 输出

按任务生成 audit.csv、continuation.json 和独立续算目录。记录有效末步、目标、恢复起点、缺失证据及参数变化。文件哈希可作来源说明或诊断，不能作为启动、提交或续算的阻断条件。

## 使用约定

- 依赖路径、环境名称、调度资源和科学参数从当前请求、项目文件或运行配置获取；只读探测缺失的环境信息，关键科学选择不明确时再询问。
- 保留源数据与既有结果，使用新的输出位置；提交、取消作业或破坏性操作须在当前授权范围内进行。准备输入本身不等于授权提交。
- 生成的脚本采用顶部配置、清楚的输入输出和相对资源引用。当前运行的本机路径可以记录在运行产物中，不回写到可分享的技能文件。
